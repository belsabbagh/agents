# agents

One global setup for [opencode](https://opencode.ai), [Codex](https://developers.openai.com/codex), and [Claude Code](https://code.claude.com) — a shared instruction file (`AGENTS.md`), a skill collection, and an install script that symlinks everything into each tool's global config. No duplication: edit here once, every tool on every machine follows.

## Layout

```
AGENTS.md     Global instructions, symlinked into all three tools
skills/       Agent Skills (agentskills.io spec), one <name>/SKILL.md per skill
agents/       Subagent definitions (markdown; opencode + claude)
hooks/        Claude Code hook scripts
install.sh    Symlink everything into place (see below)
uninstall.sh  Remove the symlinks
```

## Install

```bash
git clone <this-repo> ~/agents
~/agents/install.sh
```

Selective installs:

```bash
~/agents/install.sh --agents opencode claude   # only these tools
~/agents/install.sh --skills using-jq using-rg # only these skills
~/agents/install.sh -a codex -s using-uv       # short flags
~/agents/install.sh --dry-run                  # preview, change nothing
```

Existing files are backed up to `<path>.bak.<timestamp>` before being replaced. Tools that aren't installed yet are harmless to install for — the directories are just ready when they arrive.

Updating on any machine is `git pull` — symlinks mean no reinstall. New skills added to `skills/` need one re-run of `install.sh`.

## What goes where

| Repo path | opencode | codex | claude code |
|---|---|---|---|
| `AGENTS.md` | `~/.config/opencode/AGENTS.md` | `~/.codex/AGENTS.md` | `~/.claude/CLAUDE.md` |
| `skills/<name>/` | `~/.config/opencode/skills/` | `~/.agents/skills/` | `~/.claude/skills/` |
| `agents/*.md` | `~/.config/opencode/agents/` | — (codex uses TOML) | `~/.claude/agents/` |
| `hooks/*.sh` | — | — | `~/.claude/hooks/` (+ registered in `settings.json`) |

All locations are each tool's documented global/user scope. Codex and opencode both read `~/.agents/skills/` natively; opencode additionally reads its own config dir, which is what we use for it.

## Authoring conventions

- **Skills** follow the [Agent Skills spec](https://agentskills.io). Frontmatter is limited to spec fields (`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`) so skills load identically everywhere — tool-specific fields are ignored elsewhere and break some upload paths.
- `name` must match the directory name and be `^[a-z0-9]+(-[a-z0-9]+)*$` (opencode requirement).
- `description` decides when the skill triggers — front-load the use case; keep it under 1024 chars.
- **AGENTS.md** stays tool-agnostic (no `/command` vs `$skill` syntax) and short — Codex caps combined instructions at 32 KiB, Claude Code guidance is ~200 lines.
- Keep secrets and machine/work-specific data **out** of this repo.

## Notes

- The claude hook (`hooks/block-nonrg-grep.sh`) requires `jq` at runtime; install.sh registers it in `~/.claude/settings.json` (with a backup) or prints a manual snippet if `jq` is missing.
- Codex subagents use TOML files under `~/.codex/agents/` — not yet generated by install.sh.
